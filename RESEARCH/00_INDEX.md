# RESEARCH/ — Index

Rewrites and expansions of research papers relevant to this project's
goal of making LLMs reliable at exact computation. Each paper is split
into multiple documents organized **by concept**, not by paper
structure — which keeps each mechanism in one place and makes reading
paths cleaner.

Three source papers, six documents.

## Papers covered

### Percepta — "LLM-Computer" (Mar 2026)

Two Percepta Research blog posts arguing that transformers can execute
programs natively, faster than standard autoregressive decoding allows,
with weights generated by an analytical compiler rather than training.

- **[`01_LLM_Computer_Overview.md`](01_LLM_Computer_Overview.md)** —
  What & why, demos, caveats, roadmap. No math.
- **[`02_Fast_Attention_2D_Heads.md`](02_Fast_Attention_2D_Heads.md)** —
  The decoding-speedup mechanism: 2D heads, parabolic keys, convex-
  hull queries, HullKVCache.
- **[`03_Compiling_Programs_to_Weights.md`](03_Compiling_Programs_to_Weights.md)** —
  The analytical compiler: ALM, CALM, gate graph IR, MILP scheduling,
  WASM interpreter, partial evaluation.

Sources: Tzamos et al., *Can LLMs Be Computers?* (Mar 11, 2026);
Percepta Research Team, *Constructing an LLM-Computer: From programs
into transformer weights* (Mar 25, 2026).

### HRM — Hierarchical Reasoning Model (2025)

A 27M-parameter brain-inspired recurrent model that beats CoT LLMs on
ARC-AGI, Sudoku-Extreme, and Maze-Hard with only 1,000 training
examples per task — without pretraining or CoT supervision.

- **[`HRM/01_HRM_Overview.md`](HRM/01_HRM_Overview.md)** — What & why,
  results, brain correspondence, caveats. No math.
- **[`HRM/02_Hierarchical_Convergence.md`](HRM/02_Hierarchical_Convergence.md)** —
  The core architectural mechanism: two-timescale dynamics, why
  cycle boundaries reset the L-module, forward-residual evidence,
  Participation Ratio dimensionality hierarchy.
- **[`HRM/03_Training_Procedure.md`](HRM/03_Training_Procedure.md)** —
  One-step gradient (DEQ + Neumann), deep supervision, ACT (Q-learning
  halting), Llama-style architectural details.

Source: Wang et al., *Hierarchical Reasoning Model*, Sapient
Intelligence, 2025.

## How the papers relate

Both Percepta and HRM are answers to the same underlying question:
**the fixed-depth Transformer is not the right substrate for exact
reasoning or algorithmic computation.** They answer from different
angles:

|  | Percepta | HRM |
|---|---|---|
| **Where does depth come from?** | Extended autoregressive trace, decoded in `O(log t)` per step via 2D heads + HullKVCache | `N` cycles of `T` inner steps, each cycle a stable local computation |
| **How are the weights generated?** | Compiled from a high-level language (CALM) via MILP | Trained end-to-end on 1,000 examples per task |
| **How is correctness ensured?** | Analytically, by construction of the compiled weights | Empirically, via gradient-based learning from examples |
| **What does the "trace" look like?** | WASM execution tokens | Internal hidden-state dynamics (no explicit tokens) |
| **What's the attention doing?** | Exact keyed memory lookup (2D heads + parabolic keys) | Standard encoder attention, Post-Norm, RMSNorm |
| **What's the big open question?** | Does training 2D-head models at scale work? | Does the architecture transfer beyond symbolic grid tasks? |

**The two approaches are complementary**, not competing. Percepta
gives you provably correct computation at the cost of compiling
programs into weights. HRM gives you reasoning that emerges from
training at the cost of task-specific models. Both sidestep CoT.

A hypothetical best-of-both-worlds system would compile **core
execution primitives** into weights (Percepta-style) and train a
surrounding **hierarchical reasoning loop** (HRM-style) to dispatch to
those primitives — a latent-space analog of "LLM + tool use" where
the tools live inside the model's own forward pass. Neither paper
does this; it's the obvious next research direction.

## Cheat sheet

### Percepta concepts

| Concept | One-liner |
|---|---|
| **In-model execution** | Model's own forward pass produces the execution trace; no external interpreter. |
| **Trace-as-memory** | Generated tokens are the simulated machine's memory; attention is the read primitive. |
| **2D heads** | `d_head = 2`. Enables geometric fast path. Total parameter count unaffected. |
| **Hard-max attention** | `argmax_j (q · kⱼ)` instead of softmax-weighted sum. |
| **Parabolic keys** | `kⱼ = (2j, −j²)`, `q = (i, 1)` → argmax at `j = i` exactly. |
| **HullKVCache** | Online convex hull over 2D keys; supporting-point query in `O(log t)`. |
| **k-sparse softmax** | Nested hulls; top-k retrieval + local softmax; `O(k + log n)`. |
| **ALM** | Append-only Lookup Machine. Five primitives, Turing-complete, transformer-native. |
| **CALM** | DSL over ALM; programs compile to gate graphs. |
| **Gate graph** | DAG of LookUp + ReGLU gates wired with linear combinations. |
| **LookUp gate** | 2D-head attention with exact keyed lookup via parabolic keys. |
| **ReGLU gate** | FFN neuron computing `a · ReLU(b)`; exact products and indicators on integers. |
| **Cumsum via uniform keys** | Equal keys → uniform average → `(t+1) · avg` = exact prefix sum. |
| **Step function** | `1[z ≥ 0] = ReLU(z+1) − ReLU(z)`; exact on integers. |
| **MILP scheduling** | Integer program placing gates in layers, minimizing peak live-value count. |
| **Interval coloring** | Packs non-overlapping value lifetimes into the same residual-stream slot. |
| **Universal executor** | Interpreter in weights, program in prompt. |
| **Specialized executor** | Partial evaluation bakes `N`-instruction program into `2N` ReGLU neurons. |
| **First Futamura projection** | Specialize `interp(program, input)` for fixed `program` → dedicated executor. |
| **Weights as deployment target** | Ship algorithms by compiling them directly into weights. |

### HRM concepts

| Concept | One-liner |
|---|---|
| **HRM** | Hierarchical Reasoning Model. 27M-param recurrent architecture; two coupled modules at different timescales. |
| **H-module** | Slow, abstract planning. Updates once per `T` low-level steps. |
| **L-module** | Fast, detailed computation. Updates every step, conditioned on current H-state. |
| **Hierarchical convergence** | L converges to local equilibrium within each cycle; H update resets L's dynamics into a new basin. `N` stable nested computations per forward pass. |
| **Premature convergence** | Standard-RNN failure mode: state reaches fixed point; further iterations do nothing. HRM avoids via H-driven context resets. |
| **BPTT** | Backpropagation Through Time. `O(T)` memory. Biologically implausible. |
| **DEQ** | Deep Equilibrium Model. Compute gradients at fixed points via Implicit Function Theorem. `O(1)` memory. |
| **One-step gradient** | Keep only the `I` term from `(I − J_F)^(-1) = I + J_F + J_F² + …`. Neumann series' first term. |
| **Deep supervision** | Run multiple forward "segments" per example; detach state between them. Dense gradient signal, `O(1)` memory. |
| **ACT** | Adaptive Computational Time. Q-learning halting head decides per-example how many segments to run. |
| **`M_max`, `M_min`** | ACT hyperparameters: hard cap on segments; minimum before halt is allowed (stochastic, for exploration). |
| **Inference-time scaling** | Model trained at `M_max = k` can be run at `M_max > k` without retraining. |
| **Post-Norm + AdamW + RMSNorm** | Gives Q-learning stability without replay buffers or target networks. |
| **Participation Ratio** | `(Σλᵢ)² / Σλᵢ²`. Smooth effective rank of a representation. |
| **Dimensionality hierarchy** | Higher-level HRM modules / brain areas have higher PR than lower-level ones. Emergent from training. |
| **Neural collapse** | Standard-DNN failure mode: final-layer features collapse to low-D subspace. HRM avoids this. |
| **Direct-pred baseline** | 8-layer Transformer, same size as HRM, same training regime. HRM's structural advantage measured against this. |
| **Stablemax** | Numerically-stable softmax variant used in small-sample experiments. |
| **Adam-atan2** | Scale-invariant Adam variant. HRM's optimizer. |

## Open questions (cross-paper)

Consolidated from both papers' limitations sections.

- **Training 2D-head models at scale.** Percepta's weights are
  compiled, not trained. HRM's are trained but task-specific. Neither
  shows a 2D-head recurrent model trained to general-purpose
  capability on language.
- **Exact computation + flexible reasoning in one system.** Percepta
  and HRM each solve one half of "LLMs can't reason + compute." No
  system combines both.
- **Memory that doesn't grow with tokens.** Percepta's "memory = trace"
  means programs that use memory produce long traces. HRM's recurrent
  state is bounded but task-specific. Both have open architectural
  questions about scaling memory.
- **Training across tasks / composability.** HRM is per-task;
  Percepta is per-program. Whether either approach can transfer or
  compose across tasks is open.
- **Softmax with log-time decoding.** Percepta's HullKVCache speedup is
  natural for hard-max; full softmax at scale is approximate
  (k-sparse). Open whether exact softmax admits any geometric fast path.
- **HRM beyond symbolic grid tasks.** All demonstrated HRM tasks are
  grid-based. Whether the architecture transfers to language, multi-
  modal input, or open-ended problem solving is untested.
- **One-step gradient approximation error.** HRM's theoretical
  foundation assumes `‖J_F‖ < 1`. The quality of the approximation
  across different architectures and tasks is uncharacterized.
