# HRM-Text-1.58 Workflow Rules

The active training lane is **`hrm-158-base`** — a robust all-rounder native
HRM-Text-1.58 checkpoint grown by progressive checkpoint curriculum. This is
the canonical current workflow. PT / DT / CRLM / SubstrateLM guidance in
`training.md` is **legacy/adjacent** (retrieval + structure-extraction lanes),
NOT this lane.

> Historical receipts (per-slice measurements, chain-head provenance, msg IDs,
> ruled-out runs) live on the **ai-room board** + the commit log, NOT in this
> eager-tier rule. Keep this file current-invariant only.

## Model lane

- Native HRM-Text-1.58, **Tier-B ~29.6M** params: `hidden=512 n_layers=8
  (half_layers) num_heads=4 head_dim=128 expansion=4 H_cycles=2 L_cycles=3
  max_len=384`.
- **Broad byte tokenizer fixed** across math / language / code (`vocab=260`,
  normalizer `byte_utf8_v1`). DO NOT swap mid-curriculum.
- **Response-only loss**: prompt/instruction tokens masked; loss only on
  generated response tokens.
- Ternary bulk linears (BitLinear on q/k/v/o/gate/up/down; `lm_head`/`embd`/
  norms stay FP). Native ternary training kernel preferred
  (`--use-native-ternary-train`).
- Fast probe path is the default: cached ternary inference + KV decode cache +
  batched probe eval.

## Operating loop

Start from the **latest banked parent only** → train **one auditable
finite-support capability slice** (full-density when small enough to audit
completely; bounded fallback otherwise) → replay important priors in the same
run → validate → bank only on hard gates. One slice at a time.

- **Code/tooling slice lands before launch.** Rung generator + partition +
  tests + CLI commit and validate before any training run uses them.
- **No `.pt` commits by default** — `.pt` are runtime/research outputs. Commit
  code/tooling/docs/manifest receipts; chain-head provenance (path + recipe +
  audit result + residuals) goes on the ai-room board.

## Bank rule (hard gate)

**Acquisition ≥ 90%, retention ≥ 90% — but the two gates apply to different
surfaces.** Conflating them is a recipe error. (Retain bar is 90%, gabe-locked;
the active acquire target is the FINITE support exactly — e.g. a 90-row
identity support banks at exactly 90/90.)

- **Acquire (≥ 0.90 strict-exact, exact-finite for small supports)**: the
  **active target slice** — the new capability this run adds.
- **Retain (≥ 0.90 strict-exact OR parent-relative no-new-broad-cluster)**:
  ONLY **true prior / banked surfaces the parent actually has** (`L0a`, `L0b`,
  `math_a0`, anchors). Named hard sentinels (e.g. an anchor row-count) keep
  their explicit count.
- A surface the **parent has NOT acquired is a progress / acquisition
  diagnostic, NOT a 90% retain gate.** Example: a full-density set whose
  sibling the parent solves only ~half — its un-acquired rows are being
  *acquired*, not *retained* (gating them ≥0.90 mis-gates the target).
- A same-template **close sibling** (e.g. one-digit `L0c1` under a two-digit
  identity slice) is **watched and reported under explicit gate semantics**:
  numeric ≥90% OR parent-relative no-new-broad-cluster / parent-floor. It is
  NOT a separate hard gate above the retain bar, but it **CAN block bank** on a
  broad parent-relative cluster (3+ same-surface holes) — see the L0c1 lesson.

Bank the **earliest** save that clears all gates — the final checkpoint has no
privilege. Promote only after sampled probes + exhaustive finite-support audit
+ explicit watch rows clear **under the named gate semantics** (true priors at
the ≥90% retain bar; close siblings reported, blocking bank only on a broad
parent-relative cluster when that is the declared semantics).

## Slice-size rule

**Default (gabe-locked): auditable full-density finite support, trained
slow-safe, protected by replay+pc on acquired priors — with bounded stair-step
as the fallback only after a classified collision or oversized support.** Full
coverage of a small, exhaustively-auditable support is the default — do not bank
sparse sub-samples. Treat the recipe as one atom, not two separable defaults —
full-density WITHOUT slow-safe learning is not the method.

- **Full-density / exhaustive finite support is the DEFAULT** when the target
  support is small / auditable. Natural atoms are usually ~100-150 rows (~120
  when the surface lands there), not exact-120 universal. Train/audit the
  complete support; do not bank a sparse sub-sample.
- **Bounded stair-step (~230-row style) + ≤ 1500-step windows is the FALLBACK**
  — use it when a dense slice exceeds safe support size, OR when a full-density
  slice produces a **classified retention collision** (a parent-relative cluster
  on a close sibling that does not recover under replay+pc within the window).
- Lesson (still load-bearing): *continuing + re-warming* an already-fragile
  dense surface showed broad regressions ≤1500 steps could not recover — start
  full-density slices from a **clean banked parent**, do not continue-and-rewarm
  a fragile one.

## Recipe band

**Slow-safe learning is LOAD-BEARING in the default method (gabe-locked), not an
incidental knob.** The banked recipe is full-density support PLUS slow-safe
learning — not high-pressure fitting:

- **LR ~`5e-5`**, replay-heavy ~`.80`, `--curriculum-n-train 12000`,
  heldout/eval `200` diagnostic unless promoted, seeds 17/17, pc/temp `1.0` on
  ACQUIRED priors only, fixed Tier-B; saves at 250/500/750/1000/1250/1500.
  Step250 catches plumbing/liveness/material deviation/catastrophic retention;
  step500 is the first acquisition climb read.
- **No knob escalation on a miss** — do NOT stretch runway, bump LR, or change
  model size. Classify + split/protect/redesign instead.
- **Mild hard-stratum emphasis only** (≈1.25×–1.5×) when a stratum needs it.
  Heavy emphasis (3×) starves the easy stratum — observed crash. Not a magic
  universal config: **the curriculum boundary dominates the LR/emphasis knobs.**

## Retention mechanisms

- **Load-bearing**: explicit replay over important priors + **parent consistency**
  (pc; KL toward the frozen `--load-from` parent on prior rows) +
  **broad retained supports** (`L0b`, `math_a0`).
- **Run-specific retained-support KL pins** are explicit launch-command entries
  with non-dry ENABLED count/hash; never default-on or applied to the target.
- **Close-sibling protection when the target shares a template / emission
  surface**: a sibling that shares the wrapper (e.g. one-digit `equals what?`
  under a two-digit identity slice) is protected only by replay+pc, NOT a direct
  retained-support KL. When the target shares a surface with a banked prior,
  add **direct protection** (pin the sibling stratum as a retained-support KL)
  or **interleave** the sibling into the slice so the template isn't
  target-only — don't rely on broad replay+pc alone.
- **Never parent-KL an acquisition target.** Parent consistency (pc) and
  retained-support KL protect only surfaces the parent has *acquired*; aiming
  either at an unacquired surface pins those rows at the parent floor and
  *suppresses* acquisition — the opposite of intent.
- **Anchors are cheap sentinels / edge-case stabilizers, NOT the primary
  retention mechanism.** Don't lean on them to carry retention.
- Avoid singleton / dense whack-a-mole except as a diagnostic.

## Failure-mode classification

Classify BEFORE changing recipe:

| Class | Signal | Repair |
|---|---|---|
| **Train-set miss** | row IS in train, decodes wrong | targeted singleton repair; no curriculum redesign |
| **Held-set residual** | row NOT in train, decodes wrong | diagnostic unless promoted; track, don't redesign partitions to "fix" |
| **Parent-relative cluster** | 3+ same-surface holes a clean parent didn't have | revert / re-recipe (cluster-swap) |
| **Signal-starvation** | per-prior signal too thin under heavy replay | bump corpus size first |
| **Rewarm perturbation** | continuing+re-warming a fragile dense surface degrades it | stop continuation; stair-step bounded from a clean parent |
| **Template / surface failure** | one wrapper/template fails where others pass | bounded slice on the failing surface, not a capacity change |

**The `<expr> equals what?` lesson**: the one-digit wrapper stratum transfers
cleanly; failures concentrate in the **two-digit / template-specific** stratum
— a surface/template gap, **not math capacity**. Bank template-specific strata
via a full-density support, not a sparse sub-sample. A close sibling sharing the
`equals what?` template is a collision risk under a same-surface slice — protect
it directly.

## Curriculum stance

Arc: **math first, then language, then code.** When a slice stalls, scale by
curriculum design first: split smaller / re-stratify / protect close siblings.
Do NOT rescue the active slice by stretching runway, bumping LR, or changing
model size. Specialists and HRM-1.58-MoE branch from robust base checkpoints,
not from weak narrow experts.

## Procedure-supervised curriculum

Answer-only finite-support proves row behavior, NOT the algorithm; high acquisition only makes procedure learning plausible. Train-perfect + held-recombination-failed = **procedure not learned**: change SUPERVISION SHAPE, not answer-only range/runway/LR/model size.
- Sequence: `input/question → planning → reasoning → computing → answer/output`. Planning chooses steps/decomposition/order; reasoning justifies rules/implications; computing executes operations/state transitions; answering emits final output.
- "Planning, reasoning, and computing inside the forward target become the curriculum object." This is shaped computation supervision, NOT reward-only RL.
- Four-stage execution curriculum: explicit scaffold in answer path → recombinational held tests on trace AND final answer → mixed/partial scaffolds → answer-only transfer + retention. Gate trace/structure, parsed final answer, `too_long`/finite, and retain/collision separately.
- Same-surface targets are primary; prove prompt-only disjointness and watch `integer_only_bleed`/`trace_bleed`. Distinct-trigger fallback requires a bridging rung.
- Operator-generalization or H/L plan/compute-specialization claims require held recombination + exact/parsed trace correctness + compression/answer-only transfer persistence plus probes. Retained-support pins are KL pins, not LR.

## Validation

- **Producer/consumer watcher** for live runs (training save → rsync → probe
  bundle → OVERLAP receipt); required for fragile slices. **Only
  watcher-OVERLAP-clean saves are bank-eligible.**
- **Pre-launch box code-currency check**: the audit box is a plain rsync dir
  (not git) — verify it carries the CURRENT probe / watcher / rung files, not
  just that it's reachable. A code-currency mismatch makes the save
  non-bank-eligible until rsynced current and re-audited.
  Standing science-chain template + scripts: `claw-code-hrm-text-158/.codex/rules/box_lane_chain_template.md`.
- **Exhaustive finite-support audit** (strict-exact AND parsed-correct reported
  separately) + sampled probes + explicit **watch rows** (edge / boundary /
  known-residual).
- **Per-step receipts**; bank decisions cite the audit JSON + watch results.
- **Classify nulls as useful results** — a slice that diagnoses a failure mode
  is shippable as a committed null with the same before/after discipline.
