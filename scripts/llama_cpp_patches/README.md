# llama.cpp Out-of-Tree Patches

The llama.cpp source lives at `~/llama.cpp/` (outside this project repo) and
is NOT a git submodule. Local modifications get reverted on `git pull`. We
keep them here as patch files + full file copies so they can be re-applied
after every upstream pull.

## Files

- **`01_slot_cap.patch`** — comments out the per-slot context cap at
  `tools/server/server-context.cpp:763-766`. Lets `--ctx-size` past
  `n_ctx_train` for extrapolation testing (e.g., NIAH at 256K on Gemma 4 E4B
  trained at 128K). 1-line edit. Documented in `.claude/rules/architecture.md`
  and the NIAH eval reports.

- **`02_turboquant.patch`** — TurboQuant 3-bit KV-cache compression
  (`GGML_TYPE_TQ3_K256`). Modifies 13 existing files across ggml, ggml-cpu,
  ggml-cuda, llama-context, and llama-kv-cache. Adds:
  - Stage 1: new ggml type + block_tq3_k256 struct + type_traits entry
  - Stage 2: CPU quant/dequant reference (validated against PyTorch oracle
    via `scripts/test_tq3_k256_c_vs_python.py` — all 3 tests pass)
  - Stage 3 (CUDA): SET_ROWS kernel dispatch for TQ3_K256 + supports_op
    allowlist entry. The kernel itself is in `files/turboquant.cu`.
  - Stage 4: per-layer head_dim routing in `llama-kv-cache.cpp` (TQ3_K256 →
    Q4_0 fallback for layers with head_dim ≠ 256, e.g., Gemma 4 E4B's 4
    full-attention layers). Includes per-layer logging that emits one line
    per layer showing effective type (match or fallback).
  - Stage 5: CLI wiring in `common/arg.cpp` (`tq3_k256` canonical name +
    `tq3` short alias). Pre-scan validation in `llama-context.cpp` that
    warns when zero layers match head_dim=256 (correctly handles ISWA
    models like Gemma 4 E4B which build two separate caches).
  - CPU bug fixes (session 11): added `quantize_row_tq3_k256` wrapper +
    `ggml_vec_dot_tq3_k256_f32` to `ggml-cpu/quants.c` and registered the
    type in `ggml-cpu/ggml-cpu.c:type_traits_cpu`. Required for SET_ROWS
    and Flash Attention to dispatch correctly on the CPU backend.

- **`files/turboquant.cu`** — NEW file. Single-TU CUDA implementation:
  per-block quantize device function, SET_ROWS kernel + host launch wrappers
  (i32/i64 index variants), device-side Pi rotation matrix + Lloyd-Max
  codebook, lazy host init via `std::call_once`. Drops at
  `~/llama.cpp/ggml/src/ggml-cuda/turboquant.cu`.

- **`files/turboquant.cuh`** — NEW file. Header declaring the host-callable
  entry points (`ggml_tq3_k256_ensure_cuda_init`,
  `ggml_cuda_set_rows_tq3_k256_i32`, `ggml_cuda_set_rows_tq3_k256_i64`).
  Drops at `~/llama.cpp/ggml/src/ggml-cuda/turboquant.cuh`.

- **`files/turboquant_tables.h`** — NOT included here. Generated by
  `scripts/generate_turboquant_tables.py`. Contains the 256×256 Pi
  rotation matrix as a `static const float[]` (~1.2 MB). Regenerate
  on demand:

  ```bash
  python3 scripts/generate_turboquant_tables.py  # writes to ~/llama.cpp/ggml/src/turboquant_tables.h
  ```

## Apply order (after a fresh `git pull` on llama.cpp)

```bash
cd ~/llama.cpp

# 1. Slot cap patch (always)
git apply /mnt/c/Users/gabes/projects/claw-code/scripts/llama_cpp_patches/01_slot_cap.patch

# 2. TurboQuant modifications
git apply /mnt/c/Users/gabes/projects/claw-code/scripts/llama_cpp_patches/02_turboquant.patch

# 3. Drop in the new CUDA files
cp /mnt/c/Users/gabes/projects/claw-code/scripts/llama_cpp_patches/files/turboquant.cu  ggml/src/ggml-cuda/turboquant.cu
cp /mnt/c/Users/gabes/projects/claw-code/scripts/llama_cpp_patches/files/turboquant.cuh ggml/src/ggml-cuda/turboquant.cuh

# 4. Generate the Pi/codebook table header
python3 /mnt/c/Users/gabes/projects/claw-code/scripts/generate_turboquant_tables.py

# 5. Force cmake to re-glob (turboquant.cu is new and the GLOB cache won't pick it up)
touch ggml/src/ggml-cuda/CMakeLists.txt

# 6. Build
cmake --build /home/gabe/llama.cpp/build --target llama-server -- -j4
```

```bash
  --ctx-size 8192 --parallel 1 \

# Expected behavior: KV cache allocates on CUDA0 ("CUDA0 KV buffer size = 7.66 MiB"),

```

## Validation status

- **CPU path** (`-ngl 0`): VALIDATED. End-to-end inference produces coherent
  text. See session 11 handoff.
- **GPU SET_ROWS only**: VALIDATED. Cache allocates on CUDA, no abort.
- **GPU Flash Attention**: NOT YET. Requires tq3_k256 dequant in
  `fattn-vec.cuh` (and ideally `fattn-mma-f16.cuh` for prefill). See
  Stage 3.5 in `.claude/MEMORY/SESSION_HANDOFF.md` for full scope and
  the discoveries that gate this work.
